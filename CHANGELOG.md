# Changelog

What changed in each release of Arteria. The release workflow copies a version's section into its GitHub release notes, so write for people running the addon.

## Unreleased

- **Renames are logged**: the system log gets a line when the page reads the router's client list for a rename and one when the rename is saved, with how many names the list holds before and after. No names or addresses.
- **`doctor` looks for known problems, and `doctor fix` fixes them** (also *d* in the menu): a hook line left by going back to 1.0.0 or by an older version, files older versions left, page files any program could change, a copy of the client list or a node session left after the page closed, and on each node, whether Arteria's script runs without anything crashing. What only you can fix it reports, and nothing in it names a device or an address.
- **A node where something crashes says so**: when a command on a node crashes while Arteria reads it (*Segmentation fault*), the page says so instead of "isn't answering", and `nodes test` (like `doctor`) names the command and saves what the node ran, without addresses, to `/tmp/arteria/node-trace.txt` for a bug report.
- **Only root can change the page's files**: the router starts Arteria from its service-event script with nothing masked, so the page's data files and their folder were writable by any program on the router.
- **A pencil after a device's name** in the live readout shows it can be renamed: the name and the pencil light up together, and clicking either opens the name field.
- **Dual WAN**: the second WAN counts as internet too, instead of as local traffic, and the Internet readout shows what each WAN carries.
- **Guest Network Pro**: wired devices on a Guest Network Pro network (a LAN port in a VLAN profile) are placed on their port, from that network's bridge as well as the main LAN's.
- **`check` no longer warns when the router has no Wi-Fi clients of its own** (all of them on a node, say): it's a note that the counters will be checked once one connects.
- **Arteria keeps out of the way of a struggling router.** While it samples it watches the load and the memory available: on a busy router it samples a third as often and opens no new node sessions (the page says a node waits for that), and on an overloaded one (or one that needs over 15 s for a sample) it stops for 2 minutes. The page says why, the system log gets a line, and `status` shows the router's load, its memory and the last pause. A router that's slow to sample is sampled less often, up to every 10 seconds.
- **The page stops asking the router to sample after a minute without samples**, says what to check, and its **Stopped** button tries again; meanwhile it only looks for a sample every 30 seconds. It used to ask the router every 8 seconds for as long as it was open.
- **The service-event hook starts Arteria for its own events only.** It used to start the script for every service event on the router. Installing or updating replaces the old line.
- **Routers already set up for passwordless logins to their nodes work as they are.** If root on the router has a key that opens the nodes (`~/.ssh/id_dropbear`, as the forum's guide and the Wireless Report addon set up), Arteria uses it, and trusts each node as root's `known_hosts` does: no `nodekey`, no password. `nodes test` names the key that works. `nodekey` still sends a password only to a node whose identity you confirmed there.
- **`nodekey` changes only what it must**: it adds Arteria's key to the router's list only for nodes no key reaches yet, warns when the list already has other keys (nodes with ASUS's own firmware take only the first),.
- **Slow nodes count as answering**: a node is judged by its own pace (up to a round every 30 seconds), not by 3 rounds of 2 seconds. `debug` shows each node's pace, how fresh its output is and how many stations it reports, plus which keys the router has for its nodes.
- **The README explains how to get a struggling router back without a factory reset**: turn off *JFFS custom scripts and configs*, reboot, then uninstall over SSH.
- **13 more kinds of device**, each with its own drawing on the map and its own icon: **car**, **EV charger**, **solar inverter or home battery**, **robot mower**, **sprinkler**, **garage door**, **smart blinds**, **smart display** (Echo Show, Nest Hub), **projector**, **VR headset**, **3D printer**, **pet device** (feeder, pet camera) and **fitness equipment** (Peloton, treadmill). Garage openers were smart-home hubs before, and EV chargers smart plugs.
- **Two more kinds: LED strip and boiler.** An **LED strip** is drawn as a strip under a shelf, its LEDs running through the colours and tinting the wall; it covers Govee strips (by name, by Govee's own host names `ihoment_H61…`, or by Govee's maker name alone), WLED, TV backlights, Tapo L900-L930, Kasa KL400-KL430, Yeelight and Nanoleaf lightstrips, and "LED strip" in several languages. A **boiler** is a wall-hung boiler with its flame flickering; it covers boiler gateways (EMS-ESP, ebusd, OpenTherm Gateway, Vitoconnect, Buderus KM200), the big boiler makers and water heaters. EMS-ESP was a thermostat before. Renaming one from Arteria gives it the router's light or appliance icon, and the name keeps it a strip or a boiler.
- **Words run together are recognised**: a name like *JohnsNas*, *KidsTV*, *nas01* or *office_printer* is read like *John's NAS*, so the same rules work for everyone's names.
- **A nickname wins over the icon the router guessed**: saving a nickname in the router's client list also saves the icon the router was showing. The name now decides when that icon is just the router's own guess, or a computer, phone, tablet, watch or console icon on a device named after a home device: a nickname like *Lounge Daikin AC* makes it an air conditioner, not the game console the router guessed. Other icons you picked still come first: a smart plug named *Hall lamp* stays a plug.
- **Devices named `amazon-…`** (Echo speakers) are recognised, and a lease with no host name no longer counts as one in the Device report.
- **Daikin air conditioners' Wi-Fi adapters** are recognised without a name: they call themselves `Client`, on a Murata Wi-Fi chip.
- **Many more names and makers**: phones (Motorola, Oppo, Vivo, Xperia, Samsung model numbers), tablets and e-readers, TVs (TCL, Panasonic, Fire TV Edition), streaming boxes (Kodi, LibreELEC, IPTV boxes), speakers (WiiM, Bluesound, B&O), printers by the names HP, Brother and Epson give themselves (`NPI…`, `BRW…`), cameras and baby monitors, locks, heating (Viessmann, Vaillant, Hive), lights (Twinkly, Hue lamps, Govee by its maker), hubs (IKEA Dirigera, Zigbee2MQTT, Homematic), and robot vacuums. Echo speakers are recognised by Amazon's Wi-Fi.
- **The totals in the tab bar stay put**: the internet speeds keep their width as the numbers change, and the word *Internet*, which looked like a tab and jumped left and right, is gone.
- **Labels never sit on one another**: on a crowded floor a label moves further out, beside the floor if need be, before it covers another label or another device's drawing.
- **Tap a device's drawing** to trace it, as with its label. **Map labels show no tooltip**: tap one for its details.
- **Flow rows stay put**: rows no longer resize with every sample. A row keeps the room its traffic needed lately and only grows when that traffic clearly rises, or shrinks back after half a minute of much less. The scale is kept while everything fits, and a listed device keeps its row unless a hidden one is three times busier.
- **Rename devices from Arteria**: click a device's name in the live readout, type, and press the check or the cross. The icon beside the name shows what the new name will make it while you type. The name goes into the router's own client list, so the router shows it too, with a matching icon where the router has one. An empty name brings the router's own back. Offline devices can be renamed too. Each rename starts from the router's client list as it is at that moment, so it never undoes another rename or a change made in the router's own client editor, and nothing is saved when that list can't be read. Names Arteria would ignore (ones routers fill in themselves, like `ESP-…`) are refused, and leaving the name as shown saves nothing.
- **Zoom and pan the expanded map**, like a whiteboard: the mouse wheel or a trackpad pinch zooms around the pointer, dragging or a two-finger scroll on a trackpad moves around, and **− / 100% / +** in the corner zoom in steps or show the whole map again. It never scrolls or shows empty space past the map's edges, and opens on the whole map each time. The map zooms its drawing, not a picture of it, so selecting a device at 400% doesn't flicker, and dragging and zooming stay smooth with a device traced: shadows are softened without a blur filter, and the animations wait while the map moves (the pulsing rings and LEDs, which the browser draws as separate layers, hold still, so zooming doesn't flicker either). Zoomed in, tracing another device dims the rest at once rather than fading, so that doesn't flicker either, and a label reached with Tab comes into view.
- **The expanded Flow view fits the window during a speed test**: the ribbons scale to the window's height, so one very busy device no longer makes the view scroll. It scrolls only when there are more rows than fit.
- **Short rates show their unit**: map labels, the readout and the lists read *47k*, *2.1m* and *1.25g* in bits, *47K*, *2.1M* and *1.25G* in bytes; megabits used to show as a bare number. Labels are sized for the widest numbers, so a busy device's rates never spill out.
- **Buttons and switches match**: *Mb/s · MB/s*, *Live*, *Download · Upload* and the round buttons are all the same height, with the same fill, border and text size. They're a little smaller, with room between them and the tab bar's line, and the empty line above the tab bar is gone.
- **New kinds of device: air purifier or humidifier, smart switch, door sensor, washing machine, dryer and dishwasher**, each with its own drawing and icon: a white tower with its water tank, a light switch on a piece of wall, a sensor with its magnet across a door's edge, and a washer, a dryer (an empty drum) and a dishwasher (a plain door with its control strip). Bosch, Siemens and Neff machines are told apart by the model number in their name (`BOSCH-WAX…` a washer, `BOSCH-WTX…` a dryer, `SIEMENS-SN…` a dishwasher), and Electrolux, AEG and Miele as makers are appliances.
- **Tapo, Kasa and Govee devices recognised by the names they give themselves**: Tapo and Kasa use their model number (`L630` and `KL130` are bulbs, `P110` a plug, `C200` a camera, `S505` a switch, `H200` a hub, `RV30` a vacuum), and Govee its maker and model (`ihoment_H6159_…` is a light strip, `H7121` a purifier, `H5075` a thermometer). Shelly relays are smart switches, and a *Philips Air* device is an air purifier.
- **Labels keep off other devices**: when every spot next to a device would cover another device's drawing, its label moves further out, with a longer line to its device.
- **A nickname the router saved by itself isn't used as a name**: the router's client editor fills in what it shows, so saving just an icon can store "dhcpcd-6 8 2 Linux…" or the maker's name as the nickname. The device's own name is shown instead (the icon you chose still counts).
- **Anything cut short with "…" shows in full when you point at it**: device names on the map and in Flow, a node's name, a maker, a path.
- **The line of text under the page's title is gone**, leaving more room for the map.
- **`nodekey` no longer leaves `node_key.new.pub` behind**: newer firmware's `dropbearkey` writes the public key next to a new key, and Arteria doesn't need it. Installing or updating removes one left by an earlier version.
- **Three new kinds of device**, each with its own drawing and icon: **Raspberry Pi** (a green board with its chip, pins and ports), **streaming stick** (Fire TV Stick, Chromecast, Roku Stick, with its remote) and **smart speaker** (a fabric cylinder with a light ring: Echo, Echo Studio, HomePod, Nest Audio). Apple TV, Fire TV Cube and Shield stay streaming boxes; Sonos, Bose and the like stay speakers.
- **More devices recognised by name**: Ring cameras (`minicam`, `floodlightcam`) and the Ring Chime, MyQ garage openers, thermostats (`tstat`, Lennox iComfort, Honeywell), Xiaomi and Redmi tablets (`Xiaomi-Pad-7`), Sony and Samsung TVs by model number (`KD-43X85J`), HP Envy printers in host names like `hpenvy-7640`, EV chargers (ChargePoint, Wallbox, Easee), `SP111` smart plugs, WLED light strips, subwoofers, and *kamera* for a camera. A name like *Alexa's iPhone* is a phone, not a smart speaker.
- **`nodes test` shows whether the page can read each node.** Besides key login, it runs one round of the script the page runs on each node, and reports how many devices it read and how long that took, or why it failed (with addresses and user names taken out). A node that is too slow for the page says so. `debug` no longer lists nodes as down while the page is closed, and shows each node's last SSH message.
- **`nodekey` with SSH password login turned off** (*Allow Password Login: No*): it no longer tries a password the nodes won't take. The key goes into the router's own Authorized Keys, which a node loads when it starts, and `nodekey` says to reboot the node, then run `nodes test`. The same when a node turns down passwords on its own.

## 1.0.0

The first release: a live, animated map of how traffic flows between the internet, your router, its AiMesh nodes and every device.

- **Map**: an isometric view of your network. Cables are pipes and Wi-Fi links are arcs; each packet is traffic in motion, and packets grow and bunch up as throughput rises while moving at the same calm speed. Blue is download (toward the device), orange is upload (toward the internet), violet is the AiMesh backhaul. Devices behind a node stand in its zone. On a busy network the smallest devices are grouped into a *+N more* tray.
- **Flow**: a Sankey "river" from the internet (and local traffic) through the router, each band, port and node, to every device. Ribbon width follows throughput, with Download and Upload views. Rows keep a fixed order, so nothing jumps around while you watch.
- **Tap any device** to trace its path: everything else dims, and the readout shows its download and upload, its share of the total, signal, link rate and the path its traffic takes. **Details** shows its IP and MAC address, host name, maker, system, Wi-Fi standard and channel width (or port and speed), connection time, IPv6 and DHCP lease.
- **27 kinds of device**, each with its own drawing and icon: desktop PCs, Mac desktops, laptops, phones, tablets, watches, TVs, streaming boxes, speakers, soundbars, game consoles, printers, NAS, cameras, doorbells, smart locks, thermostats, lights, smart-home hubs, air conditioners, robot vacuums, appliances, smart plugs, sensors and more. The icon you choose in the router's client list always wins; otherwise the device's name, what the router detected, and its maker decide.
- **AiMesh nodes and the router drawn as what they are**: plug-in extenders, towers, cubes, pucks, gaming routers and classic routers, by model.
- **The *+N more* tray opens a list**: tap it to see the grouped devices, busiest first, and tap any of them to trace it.
- **Private Wi-Fi addresses** are marked as such, and a device whose private address changed is recognised by its host name when that's unambiguous, so it keeps its name and icon.
- **Expanded view**: a button opens a bigger view that fills the window (or the screen), with a stand for every device on a typical home network, a third line on each label, Flow rows with address, signal and link rate, and the readout's traffic and details together.
- A **Device report** (at the bottom of the page) shows how each device was recognised, without names or addresses, for issues about a device drawn as the wrong thing.
- **AiMesh nodes, per device.** The router reads each node's own clients over a single SSH session per node, with a key only the router holds (`arteria.sh nodekey` sets it up, shows a node's fingerprint before trusting it, and keeps the key on the nodes across AiMesh syncs). Without the key, the map still shows each node's backhaul total.
- **Only while the page is open.** Sampling starts when you open the page and stops about 20 seconds after you close it or switch to another tab. Nothing runs in the background, there are no cron jobs, and samples stay in RAM.
- **Mb/s or MB/s**: a switch at the top shows every rate in megabits or megabytes per second, and the page remembers your choice.
- The *Whole network* readout splits each total into internet and local traffic (between your devices, or to the router itself), so it's clear why it's higher than the Internet figures.
- Notices for a weak or offline backhaul and for nodes that can't be read.
- A terminal menu, ready for amtm, with `amtmupdate`, `update dev [branch]` for trying unreleased changes, and a `debug` report with no names or addresses.
